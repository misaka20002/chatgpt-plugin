# Bot 响应白名单：锅巴候选只列真正的账号

Status: ready-for-human（已实现并本地验证，提交 196f455，未推送；2026-10-30）

## Problem Statement

部署者打开锅巴的「Bot 响应白名单账号」下拉，看到的不只是自己的 Bot 账号：除了 `3654696278（小派蒙｜OneBotv11）` 和 `stdin（标准输入）`，还混着 `url`、`_events`、`_eventsCount`、`xiaofei_plugin`。这些既不是账号，也不可能出现在事件上，却和真账号并排，选错一项等于把某个真账号挡在白名单之外。

成因不在本插件的候选逻辑写错，而在数据源选错：候选取自 `Object.keys(Bot.bots)`，而 TRSS 的 `Bot` 是一个只拦读的代理（`new Proxy(this.bots, { get })`），没有 `set` 陷阱，任何 `Bot.xxx = …` 都写进 `bots`。实测四类来源——宿主启动时 `serverLoad()` 里的 `this.url`、`Bot.on()` 的 `++this._eventsCount`、`Bot.off()` 移除最后一个监听时重设的 `_events`、第三方插件的 `Bot.xiaofei_plugin = {}`。脏键随部署装的插件而变，列黑名单追不上。

真正表示「已登录账号」的是宿主另一个字段 `Bot.uin`：账号连上来时由宿主与各适配器往里追加（标准输入适配器也走这条路）。白名单闸回落时读的是事件上那个 Bot 实例的 `uin`，与这张表同值但不同源；面板候选要给的，正是闸门能够对上的那组账号标识。

## Solution

锅巴「Bot 响应白名单账号」的候选改为以 `Bot.uin` 为准，`Bot.bots` 降级为「取昵称与适配器名拼标签」的来源；已保存但当前未登录的账号仍然补一行「（当前未登录）」。部署者看到的就是能答话的账号本身。

## User Stories

1. 作为多号部署者，我打开面板只看到真正能答话的账号，不会把 `url` 当成一个号。
2. 作为多号部署者，我能在候选里认出「这个号是哪个昵称、挂在哪个适配器下」，不至于选错。
3. 作为刚加了一个号还没登录的部署者，我保存过的账号即使在候选里显示「当前未登录」，也仍然可以被选中、被保存。
4. 作为先配名单后上号的部署者，我不需要等账号登录才能把它的账号填进白名单。
5. 作为单号部署者，我不需要理解宿主内部结构，列表里就我一个号。
6. 作为原版 Yunzai v3 用户，我至少能在候选里看到自己那一个账号，而不是一片空白。
7. 作为在同一个面板里手输账号的部署者，我输入的任意形态的标识（微信那种 `wx_xxx@im.wechat`）都不会被面板判定为「不像账号」而丢掉。
8. 作为装了很多第三方插件的部署者，我装什么插件都不会让这个下拉多出奇怪的条目。
9. 作为换过号的部署者，我旧号的账号仍留在名单里时，面板照旧显示它（标为未登录），而不是把它悄悄删掉。
10. 作为维护者，我不需要维护一份「哪些键不像账号」的黑名单来跟上第三方插件。
11. 作为后来接手的人，我能在代码注释与决策记录里看到「为什么不直接用 `Bot.bots`」，不会顺手把它改回去。
12. 作为排查「这个号为什么不回话」的主人，我知道白名单里缺了哪个账号，而不是被一堆假账号干扰判断。

## Implementation Decisions

- **候选来源是宿主登录账号表 `Bot.uin`**：`Array.isArray` 为真时逐个取；为假（原版 Yunzai v3，`uin` 是标量）时退化成单账号候选。不遍历 `Bot.bots` 的键。
- **`Bot.bots` 只用于拼标签**：`账号（昵称｜适配器名）`，昵称只读 `bot.info.nickname`（部分适配器把它写成 getter，未登录时读会抛错），不扩大到 `bot.nickname`——「标准输入」适配器上两者同名，会拼出重复后缀。
- **已保存条目一律保留**，不做「像不像账号」的校验：账号标识形态不可穷举，误杀一个真账号＝白名单非空时该号彻底静默，比多列一行脏值严重。
- **去重与空值处理保持原样**：按字符串去空白后去重，空白项丢弃。
- **保存侧归一化不动**：仍是去空白、丢空项、去重；面板候选的清洗不改变保存语义。
- **宿主账号表的遍历不能用 `Object.values`**：那张数组自带 `toJSON` / `toString` / `includes` 三个自有属性，用值遍历会把函数当账号。

## Testing Decisions

- 好的测试只钉外部行为：给一组「宿主账号表 + 被污染的 `bots` + 已保存名单」，问面板最终提供哪些可选项。不测内部函数怎么取值，也不为测试导出内部函数。
- 被测接缝是锅巴 schema 本身：`supportGuoba()` 返回的 `botReplyWhitelist` 字段的 `componentProps.options`。这是面板的对外契约，也是唯一需要新盖的接缝——沿用现有锅巴测试的手法，不新增模块导出。
- 用例覆盖三种输入：TRSS 形态（`uin` 数组 + 被污染的 `bots` + 已保存含离线账号与重复项）、原版 v3 形态（`uin` 标量、无 `bots`）、以及空白项的丢弃。
- 断言对象是可选值与标签：脏键一个都不出现；首项标签带昵称与适配器；离线账号那行带「（当前未登录）」。
- 先例：`test/avatarReplyConfig.test.mjs` 同样是「子进程 + `mock.module` 桩宿主依赖 + 临时 cwd 读配置 + 断言 schema」，本用例照此实现并复用其手法。

## Out of Scope

- 修宿主 `Bot` 代理缺 `set` 陷阱、改第三方插件往 `Bot` 上写属性的写法：不在本仓。
- 清理白名单里可能已存在的历史脏值：它们会继续以「（当前未登录）」显示，候选干净后不会再新增。
- `utils/bot.js` 的 `getBots()`：它有同类缺陷（把适配器实例当账号索引），但调用方在 Web 用户列表与娱乐插件，与本面板候选无关。
- 白名单闸本身的判定语义（fail-open、空名单放行、日志位置）：见 ADR 0011 与既有测试。

## Further Notes

- 决策记录：ADR 0014（`docs/adr/0014-bot-account-candidates-from-uin.md`），包含机制证据与被否掉的三个替代方案。
- 配置指南新增一条通用规则：锅巴里任何「选账号」的候选一律取自 `Bot.uin`，不遍历 `Bot.bots` 的键。
- 术语表新增「账号候选」，用来把「已登录」与「适配器已注册」两件事分开。
- 面板候选在打开面板时现算，因此账号在面板打开之后才登录也不会立刻出现，刷新页面即可。
