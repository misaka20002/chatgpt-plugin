# 能力地图面板去重与旋钮回收

Status: ready-for-agent（2026-10-28 定案：重复块是合并遗留，非双层设计）

## Problem Statement

主人在锅巴「智能模式」页里会看到两个同名开关「启用插件能力地图」，一个在「可选工具」里、一个在「绘画设置」后面。两个开关绑同一个配置键，说明却互相矛盾：后面那份写着「只读其他插件、不执行任何指令」，而这个功能现在会把指令派发进别人的插件管道。主人按字面理解去开启，就会以为什么都没发生，或者反过来以为开了个只读功能。

同一块里还挂着三个旋钮，处境各不相同：一个是审核供应商下拉，配置键和读它的代码早就删了，选了不生效；另外两个（目录展开类数上限、审核并发批数）真在跑，但说明里写的是旧口径的实测数字，与仓库其他三处的记录对不上。

## Solution

面板上这个功能只保留一个开关，位置在「可选工具」——和报错文案指向的入口一致。开关说明继续讲清楚「会改动数据的指令先回显等你回是」，但不再向用户许诺任何条数或耗时。三个旋钮全部退出面板：两个真在用的取值回到代码里的单一来源，一个从未接线的随块删除。

## User Stories

1. 作为刚装完插件的主人，我打开锅巴只看到一个「启用插件能力地图」开关，不必猜两个同名开关有什么区别。
2. 作为还没开这个功能的主人，我从开关说明里读到「会改动数据的指令会先回显等我回是」，不会误以为它是只读的。
3. 作为看说明决定要不要开的主人，我不会看到一个具体到秒的耗时承诺，因为那取决于我装了多少插件、用什么模型。
4. 作为点了开关发现没生效的主人，我按报错提示去「可选工具」能找到那个开关，不会扑空到一个不存在的小节。
5. 作为已经调过「审核并发批数」躲开限流的主人，我知道这次升级后这个旋钮不见了，行为回到出厂值。
6. 作为把「目录展开类数」调低省 token 的主人，我同样要知道面板里再也改不了它。
7. 作为选中过「能力表审核用哪个供应商」的主人，我不用再面对一个从没生效过的下拉。
8. 作为维护者，我读代码时不会遇到「面板上有、配置里没有、代码里也不读」的三方不一致。
9. 作为维护者，我看到的日志里并发数是实际跑出来的值，不是再从配置抄一份默认值。
10. 作为维护者，我在合并上游之后仍能靠一次 grep 确认这个功能的配置只有一个来源。

## Implementation Decisions

- 删除旧分节（分隔线 + 重复开关 + 三个旋钮）：这是 `50cd979` 合并上游时把两条分支各自的开关都保留下来的产物，不是设计。
- 「可选工具」那份开关作为唯一入口保留；它的说明保留使用步骤与排障，去掉「实测 N 分 M 秒 / N 条」这类量化承诺，改为「视插件数量与模型速度而定」。
- 删除两个仍在使用的配置默认值，取值由模块自身提供：目录展开上限由渲染侧常量兜底，审核并发由审核函数的默认参数兜底。不新造常量、不在编排层硬编码数字——单一来源留在原本就拥有该语义的模块里。
- 审核函数把「实际并行度」随结果返回，编排层日志改读这个值，避免配置项删除后日志里再抄一份魔法数字。
- 能力地图入口的关闭提示改为指向「可选工具」，与派发工具的报错文案同口径。
- 手动重建的回复文案去掉条数与时长，改成「指令越多或模型越慢越久」。
- 删掉旧分节后，配置默认值注释里「只读扫描」的措辞一并纠正——同一处仍在宣称只读，与实际行为矛盾。
- 渲染侧的展开上限参数与取值收敛函数一并删除：配置入口没了之后没有生产调用方，留着就是只有测试在用的旋钮。截断行为改由真实上限验证——测试造 101 个插件类，断言展开 100、未展开 1。
- 三处「功能已关闭」提示统一成同一句话，并点名分节「插件能力地图（AI 代执行）」与开关「启用插件能力地图」：此前一处说「可选工具」（开关已不在该分节下）、一处说「能力自省」、一处说「插件能力功能」，三种叫法且都指不到具体位置。
- 配置注释里那段悬空的代执行说明并入总开关注释：它原本挂在指令地图地址上方，读起来像在描述那个 URL。

## Testing Decisions

- 只测外部行为：能力地图的对外契约是「审核通过才落盘、失败沿用旧表、目录按类截断」，本次不改变这些行为，因此不新增行为测试。
- 审核函数返回值多一个字段属于向后兼容的增量，既有断言逐字段检查，不受影响；用它作为回归证据即可，prior art 是同目录的审核与表单套件。
- 面板部分没有自动化 seam：锅巴 schema 是纯数据，删对了没有测试能替你确认，只能靠 `node --check` 加 import 该模块的既有套件不红，外加人眼看面板。这一点写进交接说明，不假装有覆盖。

## Out of Scope

- 统一「能力地图 / 能力表 / 功能表 / 指令地图」四个叫法，也不动指令名。
- 加「同一 field 不许出现两次」的 lint 护栏（本轮明确否决）。
- 给「限流时把并发调回 1」重新找一条面板退路。
- 清理老用户 config.json 里已经没人读的三个残留键。
