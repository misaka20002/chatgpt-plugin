# 群友 Nuwa Skill：对齐上游 v1.0.0、优先本地记忆样本、token 分块

Status: done（工作区实现，未提交）

## Problem Statement

Bot 主人想让群友 Skill 用上「这个群已经采集过的、关于这个人的数据」，而不是每次都去翻 OneBot 历史——记忆系统明明已经存了本群原文和个人事实，工具却只走群历史接口，同一份数据采两遍，还受接口速度与风控限制。

样本预算也不对：现在是字符数（总量 60000、单块 12000），同一块的实际 token 量随内容类型浮动约 4 倍，256K 上下文的模型被浪费；主人无法通过「多给点样本」得到更完整的视角。

可靠性同样不足：分块结果只存在内存里，任一环节抛错（尤其是最后一步合成）磁盘上什么都不留，无法判断是样本问题还是合成问题，也没有「上一次生成过什么」的概念，每次从头再来。

最后，生成出来的 Skill 只是一份画像，遇到需要事实的问题不会先做功课，也没有「这条是推断、不是本人说过」的输出纪律——这正是上游 v1.0.0 已经解决、本地还没跟上的部分。

## Solution

群已授权记忆采集时，先用本地样本（本群个人事实 + 本地原文）组成证据；本地目标消息不足 30 条才回退历史扫描补足。两条来源合并成同一种记录格式，产物与报告不标注来源。

计量单位改为 token：输入预算 100000、单块 50000（最多两块、并发两块）。每块 Map 成功即落盘，失败重跑只补失败块，整轮失败也留下可诊断的报告。

生成物对齐上游结构：角色扮演规则（含「未表态主题标推断」「关键引用可分辨」两条输出纪律）、身份卡、回答工作流（问题分类 → 按心智模型推导研究维度 → 回答）、诚实边界；砍掉时间线与智识谱系。合成后跑确定性质量自检，不通过带失败项重跑一次，仍不过则交付并标注。同目标存在上一次产物时按增量更新处理，不重写整份。

## User Stories

1. 作为 Bot 主人，我想在群已授权记忆采集时直接用本地采集到的原文做样本，这样不必等群历史接口翻页、也不容易被风控。
2. 作为 Bot 主人，我想本地样本不够时自动回退历史扫描补足，这样冷群或潜水成员也能生成，而不是直接报「数据不足」。
3. 作为 Bot 主人，我不想在产物里看到「这段来自本地记忆、那段来自历史扫描」这类来源标签，因为两条路都是我同一个插件采的，标了只是噪音。
4. 作为 Bot 主人，我想让本地原文和历史原文走同一套清洗与脱敏，这样两种来源的结果没有质量差异。
5. 作为 Bot 主人，我想让最近 30 天里该成员的个人事实进入提炼背景，这样姓名、职业、长期偏好这类高价值信息不会因为近期没聊到而丢掉。
6. 作为 Bot 主人，我不想让其他群或私聊采集到的事实混进本群产物，这样产物的「只基于本群」这句声明是真的。
7. 作为 Bot 主人，我想输入预算按 token 而不是字符计算，这样同一份预算在不同内容类型下含义一致。
8. 作为 Bot 主人，我想把输入预算提到 100000 token，这样 256K 上下文的模型能被用满。
9. 作为 Bot 主人，我想单块控制在 50000 token 量级，这样单次抽取不会被过长的上下文稀释。
10. 作为 Bot 主人，我想在样本超过预算时按时间跨度等距抽样，而不是砍掉最早或最新的一半，这样视角覆盖整段时间。
11. 作为 Bot 主人，我想每块分析结果一完成就落盘，这样合成失败时我还能看到已经抽出来的东西。
12. 作为 Bot 主人，我想某一块连续失败时其余块照常落盘并进入合成，这样单块失败不会让整轮白跑。
13. 作为 Bot 主人，我想整轮失败时也留下一份带错误与块统计的报告，这样我能判断是样本问题还是模型问题。
14. 作为 Bot 主人，我想生成的 Skill 先判断问题类型（要事实 / 纯框架 / 混合），需要事实时先查再答，而不是凭训练语料编造。
15. 作为 Bot 主人，我想回答工作流里的研究维度由这次提炼出的心智模型推导，而不是一份通用的「搜相关信息」。
16. 作为群成员，我想在使用这个 Skill 时先看到一句「这是基于聊天样本的推断，不是本人」，之后不再重复，这样不会每次都被免责声明打断。
17. 作为群成员，我想 Skill 对本人从未表态的话题明确说「这是框架推断」，而不是替他编一个精巧的立场。
18. 作为群成员，我想 Skill 引用证据时能看出来是原话还是推断，这样我不会把推断当成他说过的话。
19. 作为 Bot 主人，我想生成后自动检查心智模型数量、失效条件、表达 DNA 项数、诚实边界条数、内在张力，这样明显不合格的产物不会被当成成品。
20. 作为 Bot 主人，我想自检不通过时自动重跑一次合成，这样模型偶发的偷懒能被兜住。
21. 作为 Bot 主人，我想重跑后仍不通过就照常交付并在诚实边界里写明未过项，而不是无限打磨或直接失败。
22. 作为 Bot 主人，我想同一个成员再次生成时读取上一次的 Skill 做增量更新，这样模型命名与结构保持连续，不会每轮换一套说法。
23. 作为 Bot 主人，我想增量更新只保留仍被本次证据支持的结论，这样旧产物不会把无证据的内容带回来。
24. 作为 Bot 主人，我想把单次可请求的目标消息上限从 500 提到 2000、默认仍是 500，这样预算提高后真的能换成更多样本。
25. 作为 Bot 主人，我想工具默认参数与提示文案同步说明「优先本地、不足回退」，这样我不看代码也知道它怎么取数。
26. 作为维护者，我想 token 估算只有一份实现，这样记忆提炼与群友 Skill 对「50k token」的理解不会分叉。
27. 作为维护者，我想群友 Skill 的纯逻辑模块不依赖配置与 Redis，这样它的单测可以直接跑，不用起宿主环境。
28. 作为维护者，我想合并、去重、抽样、切块、质量自检都是纯函数，这样这些行为能用数据驱动的方式测到。
29. 作为维护者，我想失败与降级路径有明确日志前缀，这样出问题能在日志里定位到是本地取样还是历史扫描。
30. 作为维护者，我想清理无用导入与过期注释，这样下一次改动不用先分辨哪些是活的。

## Implementation Decisions

**数据来源**

- 采集入口先判两个条件：记忆总开关打开，且当前群在授权采集列表里且 `switchOn` 为真；任一不满足就走原来的历史扫描路径。
- 本地原文读取用「最近原文」接口（有 20000 条上限），按原文保留天数回推时间窗，再按发送者过滤、跳过指令与空文本；不逐条按时间范围查全群原文，避免万级 Redis 往返。
- 本地目标消息达到 30 条就完全不动历史接口；不足时按「还差多少条」请求历史扫描，两批记录按消息 ID、内容摘要、文本三级去重后按时间排序取最近 N 条。
- 个人事实只读 `user_group` 作用域，过滤已归档与已过期，按重要性、置信度、更新时间排序，去重后按条数与字符双上限截断（40 条 / 4000 字）。
- 事实是第三人称转述，**只进合成阶段的背景段**，不产生证据 ID、不进入证据文件、不参与证据校验。
- 媒体表达画像：执行了历史扫描时沿用扫描得到的媒体事件与目标消息时间线；纯本地时从原文占位符（`[图片]`/`[表情]`/`[语音]`/`[视频]`/`[文件]`/卡片摘要）推导同一结构的两个数组，保证两种来源下多媒体统计口径一致。

**token 计量**

- 全仓唯一的近似 token 估算：中文（含扩展 A）1.2 字/token、其他 4 字/token，向上取整。该函数从记忆提炼模块抽出为独立纯函数模块，提炼、压缩、群友 Skill 三处共用，不再各留一份。
- 输入预算 100000 token、单块 50000 token。单块 50000 的依据是上游单次调研 agent 的输入量级（6 个 agent 累计 500k），不是随意取值。
- 抽样按 token 而不是字符：超出预算时等距抽样保时间跨度，单条仍按 2000 字截断。
- 切块按 token 累加，记录 ID 与日期计入行宽；块间不重叠，避免同一证据 ID 在两块重复计数。
- 工具参数上限定为 2000 条、默认 500 条；`maxScannedMessages` 保持 20000。

**产物与落盘**

- 运行目录在分块分析之前创建，不再用临时目录 + 重命名；每块结果写入 `references/research/chunk-NN.json`。缺少最终 SKILL.md 的目录即代表未完成。
- 整轮失败时写 `references/generation-report.json`（状态、错误、块统计），错误信息带上产物目录。
- 报告新增每块 token 数、输入 token 估算、质量自检结果；**不新增任何来源字段**。
- 生成物新增：角色扮演规则（含两条输出纪律与退出语）、身份卡、回答工作流、数据构成；保留视角定位、心智模型、决策启发式、表达 DNA、属性、价值观、反模式、内在张力、诚实边界、证据索引。
- 回答工作流的 Step 2 由合成阶段输出 `research_dimensions`（≤5 条，每条含维度与关注点）；缺失时退化为一句「按心智模型推导研究维度」的规则，不硬编码具体维度。
- 质量自检为纯函数：心智模型 3-7 个、每个有失效条件、表达 DNA ≥3 项、诚实边界 ≥3 条、内在张力 ≥2 处。不通过时把失败项作为修正指令追加到同一份合成提示词重跑一次；重跑结果失败项更少才替换。仍不通过则写入报告并在诚实边界标注。

**增量更新**

- 生成前按「群哈希 / 用户哈希 / 时间戳」定位同目标最近一次运行目录，取其中任一技能目录的 `SKILL.md`（截断 12000 字）作为增量更新上下文；没有就跳过。
- 提示词明确：只有本次证据仍支持的结论才保留，被推翻的要标成变化，不得照抄无证据内容。服务端校验继续只认本次证据 ID，因此旧结论不可能无证据存活。

**配置面**

- 不新增锅巴字段、不新增工具参数；行为按开关与授权自动判定。锅巴里这个工具开关的说明文案改为「优先使用本群记忆采集样本，不足回退历史扫描；token 预算 100k」。

## Testing Decisions

**好测试的标准**：只断言对外可观察的结果——切出几块、每块装了什么、抽样后是否还在预算内、事实选择的结果集合、自检返回哪些失败项、渲染出的 Skill 是否包含某段与是否**不**包含某段。不断言内部函数调用次数，不锁定与决策无关的具体字符数（100000 / 50000 / 30 / 40 / 4000 这类契约常量可以断言）。

**要覆盖的行为**

- token 估算：纯中文、纯英文、中英混合三段各自的期望值。
- 抽样：预算内原样返回；超预算时条数下降但首尾消息都被保留。
- 切块：预算内只有一块；超预算切成两块；单条本身超预算时仍单独成块而不是被丢弃。
- 事实选择：归档与已过期事实被剔除；按重要性排序；超过条数或字符上限时截断；同键同文本去重。
- 记录合并：本地与历史重叠的消息只保留一条；合并结果按时间升序且不超过请求条数。
- 媒体时间线：从含占位符的原文推导出的类型计数与「图文混合」判定正确。
- 质量自检：合格产物全通过；少一个模型、缺表达 DNA、缺张力、缺边界时分别报出对应失败项。
- 合成校验：`research_dimensions` 超量、空字段、超长分别被截断或丢弃。
- 渲染：包含角色扮演规则、两条输出纪律、回答工作流；不包含时间线与智识谱系；自检未通过时诚实边界出现未过项说明。

**被测模块**：群友 Skill 的纯逻辑模块（常量、估算、抽样、切块、合并、事实选择、质量自检、合成校验、渲染）。工具编排层的取数分支不做单元测试——它只做 I/O 拼接，行为由纯函数覆盖。

**先例**：记忆 V2 的纯函数用例（切分预算、候选校验）与渲染类用例（断言生成文本包含与不包含某段）。

## Out of Scope

- 上游的 Phase 5 双 Agent 精炼（多两次完整 Skill 评审调用，收益对群聊样本不明）。
- 时间线与智识谱系（需要公开资料，群聊样本推不出来）。
- 跨群 `user` 作用域事实与 `group` 公共事实。
- 新增锅巴配置项或工具参数（目标消息上限调整是唯一例外）。
- 真实模型质量评价、真实 Redis 链路验收（需要部署后人工看产物与日志）。

## Further Notes

- 术语口径：**证据** = 可引用的脱敏原文；**已存个人事实** = 本地记忆的第三人称原子事实，只作背景。两者不得混称，术语表已收录。
- 已知取舍：事实不可引用会让原文稀少时的属性覆盖度偏低；这是为了不让「引文」变成改写，属刻意选择。
- 本地原文默认只保留 30 天，且「最近原文」接口有 20000 条上限；冷群与潜水成员仍可能走历史扫描。
- 成本：输入预算翻倍后，单次生成在长消息群里可能达到 100k 输入 token 量级（两块）加一次合成、一次可能的重跑；这是「更贵但更全」的显式选择。
- 本次不提交、不建分支、不开 PR：仓库规则要求只有用户当轮明确要求才执行 git 写操作。
