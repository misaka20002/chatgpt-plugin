# 指令地图与代执行

**Status:** done

## Problem Statement

用户装了二三十个插件，机器人却不知道它们有什么指令。于是：

- 用户问「你能干什么」，模型只能凭训练记忆瞎猜，或者干脆说「我不知道」；
- 用户把指令打错一个字，模型顺着错误编一个更像样的写法，用户试了还是不行；
- 用户说「帮我签个到」，模型回一句「你可以发送 #签到」——事情没办，还得用户自己动手。

插件作者各自维护说明，格式不统一、没人汇总。而对模型来说，「这条指令能不能用、有什么前置条件、会不会删数据」比「怎么写」更重要——这些信息在任何插件里都没有。

## Solution

由地图仓按插件发布**指令地图**：每条指令的写法、说明、参数、前置条件、常见坑、失败表现、风险档。插件这边只做三件事——**下载、缓存、用起来**：

1. 启动后与每日各同步一次，只下版本变了的；
2. 把本地地图拍平成一张可检索的表，交给**查询工具**（只读）与系统提示词（只到插件级摘要，控制固定成本）；
3. **代执行**：用户说「帮我点赞」，AI 以**提问者本人**的身份把指令交回框架派发，而不是教用户怎么写。

用户视角：装好插件、什么都不用配，问一句「你能干什么」就有答案；说「帮我签到」就真的签到。

## User Stories

1. 作为一个刚装好插件的用户，我希望不用改任何配置就能用上指令地图，这样我不用先读文档才能开始。
2. 作为一个用户，我希望问「你能干什么」时得到本机真实存在的插件与指令，而不是模型的猜测。
3. 作为一个用户，我希望问「签到怎么写」时拿到正确写法与所属插件，这样我不用翻群公告。
4. 作为一个用户，我希望指令打错时被指出正确写法，而不是被顺着错误编一个更像的。
5. 作为一个用户，我希望看到某条指令的前置条件（要不要管理员、要不要绑定账号），这样我不会白试。
6. 作为一个用户，我希望在真正执行前知道它有没有副作用（会不会删数据、发消息），这样我敢不敢用有判断。
7. 作为一个用户，我说「帮我签个到」时希望机器人直接办成，而不是回一句「你可以发送 #签到」。
8. 作为一个用户，我希望代执行用的是我自己的身份与权限，而不是 Bot 的，这样不会出现「我明明没权限却执行成功」。
9. 作为一个群成员，我希望说了「帮我签到」它就真的去做，不要再反问我一遍——反复确认的流程在实际对话里会卡死。
10. 作为一个群成员，我希望管理员指令不能被别人借 AI 代执行，这样群设置不会被绕过。
11. 作为一个用户，我希望代执行只在当前会话发生，不会把内容发到别的群。
12. 作为一个用户，我希望代执行失败时得到一句人话解释，而不是英文报错或堆栈。
13. 作为一个主人，我希望看到地图的当前状态（缓存了几份、缺哪些、连续失败几次），这样出问题我能判断。
14. 作为一个主人，我希望手动触发一次更新，这样不用等每日任务。
15. 作为一个主人，我希望地图下载失败时不要天天私聊我，连续失败到一定次数再提醒。
16. 作为一个用户，我希望云端没有某个插件的地图时，机器人如实说「这个插件我没资料」，而不是编。
17. 作为一个用户，我希望地图更新后不需要重启机器人。
18. 作为一个升级上来的用户，我希望旧配置不影响新功能的行为（旧配置已全部清空，按全新安装处理）。

## Implementation Decisions

### 数据来源与格式

- 默认地图源为 `Binbin-miao/command-maps` 的 `dist/index.json`（schema 2）。这是**外部数据源**，可通过配置项替换；README 与 ADR 要写明这一点，方便上游评审判断是否接受这个默认值。
- 地图格式照单全收现有 schema 2（23 个字段）。不裁剪：前置条件、常见坑、失败表现正是「该不该用」的依据。
- 地图文件按插件分布，索引给出每份的 `file`、`version`、`sha256`、`bytes`。

### 模块划分

- **地图核心只有一个文件**：读索引、比版本、下载校验、落盘、拍平、拼提示词、代执行的匹配与派发（纯函数，不直接发网络请求）。
- **两个薄工具**：查询工具（读本地地图，不联网、不执行）与代执行工具。工具只做参数校验、调用核心、拼回执；不写业务逻辑。
- **一个入口 app**：手动更新与状态查询两条指令，仅主人可用。

### 同步节奏

- 地图同步**默认开启**：启动后拉一次，之后每日一次；只发一个索引请求，版本没变不下载任何地图。
- 代执行**默认关闭**，由主人显式打开。
- 不做过期与 TTL：29 份地图总量不到 4MB，版本比对已足够。
- 连续失败达到 3 的倍数才私聊主人，避免每天报错。

### 代执行边界

- 以**提问者本人**的身份派发，不用 Bot 身份。
- 只在**当前会话**执行，不跨群。
- 不做「先问用户」的确认，也不在工具里预判权限：用提问者本人身份派发，能不能执行由框架的规则与插件自己的校验决定。`risk` 只用于日志与模型判断，不挡执行。
- 权限一律交给框架与插件：工具不预判、不预检，没有权限时由框架回「暂无权限」、插件报自己的错，工具把这份结果如实转达。
- 派发**交回框架**（`loader.deal`），权限位与事件过滤由框架判定，不自行调用插件函数。

### 提示词注入

- 只到「插件 + 一句话 + 条数」这一级，单条细节由查询工具按需取；固定成本跟插件数量走，不跟指令总数走。
- 没有可用地图时注入空串（静默降级，不是错误）。
- 代执行关闭时，提示词里要说明「只能告诉用户写法，不能替他执行」。

### 配置

- 两个开关：指令地图（默认开，管同步与查询）、代执行（默认关）。关掉前者后不再拉取、也不再让 AI 查询（缓存保留）；按 AGENTS.md「工具注册由配置开关控制，不新增无条件注册」，查询工具不能常驻。
- 一个数据源地址，默认指向上述索引。
- 不做旧配置迁移：旧配置已清空，按全新安装处理。

## Testing Decisions

**好测试的标准**：只测外部行为——给定输入与桩，断言输出与落盘结果；不断言内部函数调用顺序，不复制实现细节。

**测试缝**（沿用上游既有做法，见 `test/githubTool.test.js`）：

1. **地图核心**：导出函数一律接受注入的 `fetchImpl`，测试直接调用——这是最高、也是唯一需要的缝。临时目录靠测试里 `process.chdir` 切：Node 的 `fs` 没有注入点，为了测试给每条读写路径加一个 root 参数，改动面远大于收益（评审两轮都提过，这里明确记为取舍）。
   - 读索引：schema 不对、缺 plugins、非 JSON → 报错且不抛原始堆栈。
   - 比版本：本地没有要下；版本相同跳过；云端没写 version 时按 sha256 判等（防止每轮全量重拉）。
   - 下载：哈希不符、schema 不符、正文 `plugin.key` 与索引 key 不符 → 拒收且不落盘；一份失败不影响其余。
   - 拍平：一条指令产出一条条目，字段齐全；空地图不产生条目。
   - 提示词：没有地图返回空串；有地图时包含插件名与条数；代执行关闭时包含「不能替你执行」的说明。
2. **两个工具**：实例化后调用，桩掉 `Config` 与 `globalThis.logger`；断言回执文本与「是否真的派发」。
3. **代执行派发**：注入一个假的派发器（`setCommandDispatcher`，生产环境是 `loader.deal(event)`），断言：命中规则时调用一次、未命中时不调用、非主人也照样派发（够不够权限由框架判）、插件回了 0 条消息时工具报失败。不测 `loader.priority`——派发交给框架，工具只负责把事件交出去。

**先例**：`test/githubTool.test.js`（工具 + 纯函数 + 注入 fetch + 真实 http 兜底）、`test/emojiLikeTool.test.js`。

**必须锁住的回归**：
- 云端无 version 时不得每轮重拉（旧实现踩过）。
- 索引把 A 的地图指到 B 的 key 时必须拒收。
- 默认索引地址被改错时，测试要能红（用真实默认值做断言，而不是测试里另写一份常量）。

## Out of Scope

- **本机扫描 + 模型审核生成能力表**：那是另一条产品线（本地枚举、花钱审核），本次不做。
- 地图的编辑/上传工具：地图在地图仓里手写维护。
- 地图版本回滚、灰度发布。
- 多语言地图。
- 为旧版本配置做兼容或迁移。

## Further Notes

- 已合并的旧实现在 `Binbin-miao/chatgpt-plugin` 的 `backup/v2-20261029` 分支，仅作参考；`v2` 已重置为上游 `1e22f36`，新实现从干净基线开始。
- 有一个值得单独记 ADR 的取舍：**默认数据源指向个人仓库**。上游评审可能不接受，但换成「必须手动配置」会让开箱即用不成立。ADR 要写清替代方案与退路。
- 代执行的事件伪造必须用测试锁住：它绕过了正常的消息入口，一旦框架调整事件形状，这里会静默失效。
