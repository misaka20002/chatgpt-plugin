# 03: AI 能查到指令，提示词里也有插件清单

**What to build:** 接上查询工具与系统提示词。用户问「你能干什么」「签到怎么写」时，模型先看提示词里的插件清单，再调工具拿具体写法；本地没有地图时提示词不注入任何东西，工具如实说「还没拉取」，不编造。

**Blocked by:** 02

**Status:** done

- [x] 有地图时，提示词包含「插件名 + 一句话 + 条数」，且不含单条指令细节
- [x] 没有地图时提示词返回空串（静默降级，不报错）
- [x] 查询工具按插件名返回该类整批指令（超过 40 条时截断并说明），按关键词返回匹配项
- [x] 查不到时明确否定，并说明「不代表不存在」
- [x] 工具只读本地地图：全程不发任何网络请求
- [x] 本地没有地图时工具返回「先去更新地图」，并指出可用指令
- [x] 代执行关着时，提示词里多一句「只能告诉用户写法，不能替他执行」

## 落地

`buildPromptAddon({ entries, delegated, missing })` 与 `searchEntries(entries, query)` 加进地图核心，纯函数。
`CommandLookupTool`（`commandLookup`）只做参数校验与回执拼装，由地图开关控制注册（原写成「常驻、
不受开关影响」，与 AGENTS.md:74「工具注册由配置开关控制」冲突，第三轮评审后改为受开关控制，见票 06）。
注入口在 `collectTools()` 末尾的 `systemAddition`——**四个 provider 分支都会带上**：Gemini 那一支此前
只解构了 `funcMap`，把 `systemAddition` 整块丢掉（连群管用的 `message_id` 一起丢），本轮一并补上。

**匹配顺序是被真实数据逼出来的**：插件名完全对上（含去掉尾部括注、对上 `pluginKey`）才给整批；
否则先看指令与关键词；指令一条都不中才退回插件名「沾边」。起因是全库 29 个插件里有个叫
「GT 手动签到」的，查「签到」时若按插件名先命中，就只回它那 3 条冷门指令，而全库实际有 37 条。
修前修后都量过：现在查「签到」回 37 条（列前 12），查「喵喵插件」回 77 条整批。

**拍平结果加了记忆化**：每条消息都要用这张表，29 份地图 2.6MB 重新解析要几十毫秒并堵住事件循环。
失效不看时间，看「目录名 + 各 `entry.json` 的 mtime 与大小」算出的签名——同步落盘与手工改文件都会变。
实测：首次 27ms，命中缓存 0ms。提示词 2926 字符（29 个插件 1177 条指令），只到插件级。

代执行开关读 `Config.enableCommandMapDelegate`，键还不存在时取到 `undefined` → 按关闭处理，
提示词写「只能告诉用户写法」。票 06 只需把这个键补进配置默认值。

**回执分两档**：问具体指令（非插件命中且不超过 3 条）时展开「做什么/耗时/花费/前置/坑/失败长这样/边界」，
问插件时只给清单——一个插件几十条，逐条展开会把回执撑成几千行。失败一律以 `Error: ` 开头（对齐
`docs/agent-guides/tools.md`「失败要显式标记为错误」），不能和正常结果长得一样。

测试 27 项（`test/commandLookupTool.test.mjs`）：提示词空串/单条细节不泄漏/排序/代执行两种口气/无一句话、
插件名精确与 key、括注、沾边但指令有命中、沾边且指令无命中、写法精确优先、别名与关键词、
参数非字符串、工具在无地图/缺查询词/查不到时的三种说法、schema 形状。
真数据冒烟：29 个插件 1177 条，五种查询各验一遍。
