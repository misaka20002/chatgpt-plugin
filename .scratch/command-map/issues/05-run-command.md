# 05: AI 能替用户把指令发出去

**What to build:** 用户说「帮我签个到」时，AI 匹配到指令后以**提问者本人**的身份把指令交回框架派发，框架照常判权限、跑插件，结果由插件自己回复。不做确认、不预判权限，用户明确要了就执行；只在当前会话发生。

**Blocked by:** 02

**Status:** done

- [x] 命中唯一写法时交给框架派发，不自己调用插件函数
- [x] 命中多条候选时返回候选让模型选，不擅自执行
- [x] 一条都没命中时说清「没找到」，不编造
- [x] 以提问者身份派发（不是 Bot 身份），权限位由框架判定
- [x] 不做确认：用户明确要了就直接派发；权限与结果由框架和插件决定
- [x] 不预判权限：非主人也照样派发，够不够由框架判
- [x] 只在当前会话派发，不接受「发到某个群号」这种参数
- [x] 插件执行报错时回一句人话解释，不贴堆栈与路径

## 落地

`resolveCommand(entries, text)` 加进地图核心，`CommandRunTool`（`commandRun`）是薄工具。
注册条件是 `Config.enableCommandMapDelegate && !e.__commandMapNested` —— 默认关（键还不存在时取到
`undefined`），且派发出去的回合不再注册自己。

**派发就是造一个「用户自己发了这条指令」的事件**：`Object.create(原型) + Object.assign(e)`，
只改消息内容三类字段（`msg / raw_message / message`）与三个「这条消息是不是在 @ 我」的标记
（`isAt / atme / hasAlias`，否则可能被当成对 Bot 的定向呼唤），群号、发送者、`isMaster`、Bot 实例
全部原样继承，然后交给
`loader.deal`。权限、频率、事件过滤都还是框架那一套——自己调插件函数等于绕开它们重写一遍。

**不做确认，也不预判权限**（2026-10-29 定稿）：用户明确说了「帮我签到」就直接派发，不再问一遍，
也不在工具里判断「这条是不是主人专用」。理由：派发用的是提问者本人的身份，框架会按插件规则里的
`permission` 拦、插件自己也校验绑定与额度；它们拒绝时会把自己的话发到群里。工具再拦一道，只会
出现「插件本来能用，却被地图数据按住」。

这条推翻了此前两版设计：v2 早期要求模型带 `confirm` 参数，后来改成「确认必须来自下一条消息」。
两次都被线上打脸——模型拿到「先问用户」后并没有去问，而是直接回「帮你点过了」，用户看到假成功，
插件一次都没被叫醒。

**成败看插件有没有回话，不看 `deal` 的返回值**：`loader.deal()` 返回 true 只说明「事件被某个插件
接走了」，不代表它办成了——插件可能自己抛异常，也可能因为没绑账号而静默退出。所以包一层 `e.reply`
数条数，0 条就返回 `Error:` 并明确「不要声称完成」。

**重名指令按写法合并，档位取最严**：真实数据里 1177 条写法有 17 组跨插件重名。框架本来按优先级挑一个
执行，用户手打也是这个结果，所以不该因为重复就拒绝；但风险要取最高的、权限只要有一个要 master 就要
master，否则会拿某个插件的「只读」掩盖另一个插件的「有副作用」。合并后自解析 1177/1177 全部命中自己。

`loader` 用动态 import 并允许 `setCommandDispatcher` 注入：`lib/` 是宿主的东西，测试环境没有，
静态 import 会让整个模块加载失败，把纯函数的测试一起拖下水。

测试 20 项（`test/commandRunTool.test.mjs`）：解析七种情形（精确、带参数、最长前缀、别名、重名合并、对不上、空串），
代执行十三项（无地图、缺写法、正常派发的事件形状、别名歧义列候选、没命中、非主人也派发、
点赞签到直接执行、派发但插件没回话报失败、框架未认领、派发抛错不泄漏路径、带参数、
别名转正式写法、schema 只有写法一个参数）。失败回执统一以 `Error: ` 开头。
