# 06: 用户能手动更新、看状态、开关都通

**What to build:** 两条主人可用的指令——手动更新地图、查看地图状态；两个开关（地图同步默认开、代执行默认关）进配置与锅巴面板；README 与 ADR 说明数据源可替换，以及为什么默认指向外部仓库。

**Blocked by:** 03, 04, 05

**Status:** done

- [x] 手动更新指令给出完整回执：版本、本机插件数、更新几份、失败几份、缺哪些
- [x] 状态指令给出版本、缓存几份、缺失清单、连续失败次数，只读不写
- [x] 两条指令都只允许主人触发

- [x] 代执行关掉后，查询照常可用，只有代执行被拒
- [x] 锅巴面板出现两个开关，文案各自说清代价（一个不花钱、一个花钱且有风险）
- [x] README 写明默认地图源与如何替换；ADR 记录「默认指向外部个人仓库」的取舍与退路

## 落地

两条指令进 `apps/commandMap.js` 的 `rule`，都带 `permission: 'master'`：`#指令地图更新`、`#指令地图状态`。
指令名用 `UPDATE_COMMAND` 常量拼正则，避免「工具里说的指令名」与「实际注册的名字」漂移。

回执文案 `updateReport` / `statusReport` 放在地图核心里而不是 app 里：app 依赖宿主的 `lib/`，
测试引不进来；放核心里它们就是可测的纯函数。`statusReport` 的开关状态由调用方传，不自己读配置。
失败列表只列前 5 条——同一轮的失败原因多半是同一个网络问题，刷三十条等于什么都没说。

三个配置项进 `utils/config.js` 默认值：`enableCommandMapSync: true`、
`enableCommandMapDelegate: false`、`commandMapIndexUrl: ''`（留空用内置默认源，
默认地址仍只在 `map.js` 定义一处）。锅巴面板新增「指令地图」分组，两个 Switch 的说明分别写清
「不花钱、只占几 MB」与「会真的触发插件、改动数据」。

**开关口径改了**：原票写的是「关掉同步后查询工具照常可用，只提示一句已关闭」。按 `AGENTS.md:74`
「工具注册由配置开关控制，不新增无条件注册」，查询工具不能常驻；而它唯一的开关就是地图开关。
于是改成「一个开关管整套能力」：关掉后不拉取、不注册查询工具、提示词也不注入，缓存保留、重开即恢复。
锅巴文案跟着从「同步指令地图」改成「启用指令地图」，并写明关掉的影响。

README 新增「指令地图」一节：是什么、默认数据源与如何替换、两个开关的代价对比表、
两条主人指令、失败不打扰的机制。ADR 0012 早已记录默认指向个人仓库的取舍与退路，本票未改。

测试 9 项（`test/commandMap.test.mjs` 的「回执」与「开关判定」；三份文件合计 102 项）：更新回执四个字段、无事可做时也说一句、失败超过 5 条只列前 5、
索引没拉下来时不说「失败 1 份」、状态回执六项与开关、从没同步过的如实说法、开关三个默认值断言
（含「关掉后工具不再注册」所依赖的 `syncEnabled(Config)` 判定）。
