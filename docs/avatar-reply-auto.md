## 1. 图片文件夹生成与按群角色配置

更新插件后，在插件目录执行 pnpm install 安装依赖。资源根目录是 **Yunzai 根目录**下的 data/chatgpt/avatars，不是插件目录。

### 更简单的方式：放图片后刷新

每个角色一个文件夹，文件夹名就是锅巴下拉中显示的角色名，可使用中文：

```text
data/chatgpt/avatars/
  呆毛/
    normal.png
    close.png
    open.png
    happy.png
    confused.png
    angry.png
    shy.png
    crying.png
  另一个角色/
    normal.webp
    close.webp
    open.webp
```

normal、close、open 三个基础文件名固定，分别表示正常、闭眼、张嘴；扩展名接受 png、jpg、jpeg、webp，大小写不敏感。其余非隐藏图片作为特色表情，最多 32 张。不要把预览截图、对齐对比图等无关图片留在此目录。同名的不同格式文件（例如 normal.png 和 normal.webp）会报冲突。

Bot 主人执行 **#chatgpt刷新角色文件夹**。插件扫描所有直接子目录，为各角色生成或更新 peraravatar-plus-config.json；不需要先去网站制作 JSON。

默认命名：happy／开心→开心并搭配 bounce；confused／困惑→困惑并搭配 wobble；angry／生气→生气并搭配 shake；shy／害羞→害羞并搭配 wobble；crying／哭泣→哭泣并搭配 none。其他文件以文件名为表情名称，默认 none。新表情 ID 根据源文件名生成，模型仍然只使用已加载的 ID，不直接访问文件。

若已有手工 JSON，刷新优先按 sourceFile 记录匹配原表情；首次处理网站文件时按表情名称的“开心”等前缀匹配。唯一匹配后保留原 ID、名称、动作、图片位移，以及整体呼吸／眨眼设置。新表情使用默认值，删除图片会从生成列表中移除该表情。无法唯一匹配时该角色刷新失败，不猜测覆盖；若首次手工名称完全改成其他词，建议先改回标准名称完成一次匹配，再修改名称。

发生变化时先备份原文件为 peraravatar-plus-config.json.<时间>-<编号>.bak，再原子替换 JSON；没有变化时不重新写入或增加备份。缺少基础图、图片损坏、命名冲突或超限，保留旧 JSON 并显示错误。其他有效角色继续刷新。备份由主人自行保管／清理。

只有 JSON、没有图片的文件夹按手工资源处理，不重建。完整图片模式下网站遗留的 buildMode:parts 字段不会阻止使用完整立绘，真正的顶层分层模式仍不支持。路径穿越和越界目录／图片链接被拒绝。

### 在锅巴为每群选择

执行刷新命令后，重新加载锅巴配置页面。在“角色动图群”表格中分别设置：

| 字段 | 用途／可选档位 |
| --- | --- |
| Bot QQ、群号 | 对应机器人与目标群 |
| 自动附带角色动图 | 只在该 Bot＋对应渠道开启；8888 行为私聊开关 |
| 角色文件夹 | 从已存在资源 JSON 的角色目录下拉选择 |
| GIF 分辨率 | 512×512、768×768、1024×1024（全部为正方形） |
| GIF 时长 | 2、3、5 秒 |
| GIF 帧率 | 10、15、20 FPS |

「角色动图回复」分组里还有一个**全局开关「特色表情渐变过渡」**（默认开启，与「角色动图群」表格的按群字段相互独立）：开启后，辅助模型选中特色表情时按下面「特色表情的播放时间线」播放；关闭后整段播放特色立绘（旧行为）。

同一个 Bot 在不同群可以使用不同角色和画质；多个 Bot 也可以共享同一角色。未设置时默认 512×512、3 秒、10 FPS；已保存的旧 512×640 档会自动按 512×512 使用。私聊需要预览、状态或自动附图时，手动添加一行：Bot QQ 填实际值、**群号填 8888**（保留值），该行决定私聊使用的角色与档位；**打开该行开关后，私聊回复会自动附图（所有与该 Bot 私聊的用户）**。没有 8888 行或未选角色时，私聊预览/状态会提示先到锅巴配置。

也可以将以下字段合并到插件现有 config/config.json，保留其他配置；手动修改群配置后重启 Yunzai，锅巴保存立即生效：

```json
{
  "avatarReply": {
    "provider": "current",
    "groups": [
      {
        "botId": "123456789",
        "groupId": "987654321",
        "switchOn": true,
        "avatarId": "呆毛",
        "size": "1024x1024",
        "duration": 3,
        "fps": 10
      }
    ]
  }
}
```

默认没有授权群；私聊默认不附图，8888 行开关打开后所有私聊用户都会自动附图。开关不改变聊天黑白名单、冷却或模型权限。

| 主人指令 | 用途 |
| --- | --- |
| #chatgpt刷新角色文件夹 | 按图片生成／更新 JSON，显示各角色的成功或失败结果 |
| #chatgpt角色预览 | 群内使用本群选中的角色和档位；私聊不带名称时使用 8888 行 |
| #chatgpt角色预览 呆毛 | 仅私聊可指定角色目录；档位取 8888 行，没有该行时用默认 512×512／3秒／10 FPS |
| #chatgpt角色状态 | 显示当前渠道（群或私聊 8888 行）的资源路径、档位、图片数量、特色表情、开关和读取错误 |
| #chatgpt角色开启 | 在当前群/私聊开启（私聊操作 8888 行）；仅 Bot 主人可用；要求对应渠道已在锅巴选择角色文件夹 |
| #chatgpt角色关闭 | 在当前群/私聊关闭，取消尚未发送的旧任务；仅 Bot 主人可用 |

资源文件在使用时检查更新，无需为了替换图片重启。更新失败继续使用本进程中该角色上一次成功加载的资源；状态会显示错误。重启无法恢复只存在于内存中的旧版本，必须保留文件备份。切换角色或档位会取消旧的待发任务。

### 电影字幕叠加层

所有角色动图（自动附图、群聊／私聊、主人预览）统一采用**画面内的单行电影字幕**：白字、黑色描边和轻微阴影，直接覆盖在适当放大的角色立绘下部；不再使用旧气泡、箭头、底框或另留字幕区域。模型优先从完整回复中提炼最多两段自然短句，按顺序硬切换而非逐字出现；本地按标点断句和字符数兜底，切掉每段首尾的标点，长字串自动缩小字号或截短，不能自动折为两行。

字幕切换与特色表情渐变时间线互不干扰。角色输出三个档位均为正方形；旧 512×640 的历史设置读取时改为 512×512。若选择 768×768、3 秒、10 FPS，应在实际 QQ 客户端确认 GIF 仍能自动下载：改动字幕或角色大小会影响字节体积，插件自身的 8 MiB 上限不等于 QQ 的自动下载阈值。

### 特色表情的播放时间线

开启「特色表情渐变过渡」（默认开启）且辅助模型选中特色表情时，动图按三段播放：

| 阶段 | 行为 |
| --- | --- |
| 正常段（约前一半时长） | 普通立绘，眨眼与说话动嘴照常；反应动作（抖动、跳动等）此时不出现 |
| 交叉溶解（约 0.35 秒） | 从普通立绘逐渐混合到特色立绘，仍只播基础运动 |
| 特色段（不短于 1 秒，直至结束） | 保持特色立绘，反应动作在过渡完成后以约 0.2 秒缓入开始；按原眨眼节奏短暂闪回普通「闭眼」帧；不再张嘴 |

2 秒档约为 0.65／0.35／1 秒，3 秒档约为 1.5／0.35／1.15 秒，5 秒档约为 2.5／0.35／2.15 秒。模型未选中特色表情时仍按普通三帧循环播放；关闭全局开关时整段播放特色立绘（旧行为）。

### 确认插件识别

1. 放好图片后执行刷新命令，确认目标文件夹显示“已生成”“已更新并备份”或“未变化”。只复制散图不会立即生效，必须刷新。
2. 在锅巴选定角色后发 #chatgpt角色状态，确认路径、特色表情名称和档位正确。
3. 发 #chatgpt角色预览 检查基本眨眼、嘴型、布局与画质。透明背景是预期效果；预览不调用辅助模型，也不会选中特色表情，看不到渐变过渡；时长短于眨眼间隔时可能看不到眨眼（特色段的闭眼闪回同理）。
4. 在启用的群或私聊中进行庆祝、疑问、抱怨、接受夸奖、安慰等对话。辅助模型按最终回复选择特色图，也可以不选，不保证每句话都触发指定表情。
5. 生成的图片是否对齐、是否满足资源限制，以及真实提供商的选择效果，仍需用实际素材和群聊检查。

## 2. 输出与排障

输出为透明背景（GIF 只支持 1 位透明度，半透明边缘会被二值化）；分辨率、时长、帧率按渠道配置，默认 512×512、3 秒、10 FPS。图片素材若是纯白背景，GIF 里也会是白色底，想要真正透明请使用透明背景 PNG。每轮最多一张 GIF。角色字幕最多 2 段，每段不超过 12 个可见字符（合计不超过 24），始终单行、按字数分配时间并保证每段至少 0.7 秒。辅助模型只能选择已存在的表情 ID 和支持的动作；调用失败时用正文首句本地断句、清除首尾标点并采用默认动作。GIF 生成或上传失败不撤销完整文字。

本地渲染不需要 GPU、浏览器、麦克风、摄像头或 FFmpeg。工作线程串行编码，最多三项等待任务，队列满时跳过附图，生成超时为 30 秒。文件超过 8 MiB 或生成超时会跳过附图，不自动降低选定档位，完整正文保留；高分辨率、长时长和高 FPS 会增加耗时与体积。发出前再次检查群授权及资源版本，发送后清理系统临时文件。GIF 编码使用 gifenc（全局透明调色板 + rgb565 最近色匹配，并按上一帧索引做滞回以抑制逐帧色斑闪烁）；渐变仍可能有轻微色阶，QQ 客户端也可能压缩动图。

| 现象 | 处理 |
| --- | --- |
| 无法确定 Bot／找不到文件 | 用状态命令检查路径；私聊使用群号 8888 行（角色、档位与自动附图开关），其中 Bot QQ 必须等于 Bot 自身 QQ |
| 提示“未选择角色文件夹” | 群内先在锅巴为该 Bot＋群选择角色文件夹；私聊先添加群号 8888 的行并选择角色 |
| 不支持模式／口型档过多 | 选择完整图片模式，只留一个口型档及一张开口图，移除部件特色表情 |
| 图片不是内嵌数据 | 替换网站样例为自己的图片，重新下载配置 JSON |
| 特色表情超限 | 特色表情最多 32 种，同时检查 JSON 32 MiB、单图 6 MiB、累计 32 MiPixels 的资源限制 |
| 切换时角色抖动 | 检查差分对齐，在网站修正位置和大小，或重新编辑差分 |
| 首句电影字幕／没有动图 | 查看 [ChatGPT] 角色字幕／渲染／发送日志和状态命令，检查模型连接、队列及上传 |
| 特色表情没有渐变过渡 | 检查锅巴「特色表情渐变过渡」开关是否开启；辅助模型未选中特色表情时本就不进入特色段（正常现象）；关闭开关时整段播放特色立绘 |
| 中文显示方块 | 安装系统中文字体；Debian/Ubuntu 可安装 fonts-noto-cjk，安装后重启 Yunzai |
| 替换 JSON 后仍是旧角色 | 查看状态中的读取提示；修正文件后重新预览，首次失败不会创建假资源 |

人工构造的栅格测试素材仅验证状态切换、解析、权限、任务取消和 GIF 编码，不代表 GPT Image 2 差分质量。
