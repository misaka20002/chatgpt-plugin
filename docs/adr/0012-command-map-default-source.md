# 指令地图的默认数据源指向外部仓库，不做内置也不留空

状态：已采纳（2026-10-29）。需求与决策过程见 `.scratch/command-map/spec.md`。

「指令地图」是外部维护的数据：每个插件有哪些指令、怎么写、有什么前置条件与坑。它由独立的仓库按插件发布，插件这边只负责下载与缓存。于是配置里必须有一个默认地址，而这个默认值只能指向某个具体的仓库。

选择指向 `Binbin-miao/command-maps` 的 `dist/index.json`，并在 README 与配置项说明里写清「这是数据源，可以替换」。

## 考虑过的替代方案

- **默认留空，首次使用必须自己填**：最干净，但「装好就能查」这个前提直接不成立。用户装上插件、问「你能干什么」，得到的会是「还没配置数据源」——比没有这个功能更糟，因为它看起来像坏了。
- **把地图打进插件包一起发**：地图数据有独立演进节奏（插件更新频繁，地图跟着改），打进包里等于每次改一条指令都要发一版插件；而且插件包会随插件数量线性膨胀，用户还得为用不到的地图付下载成本。
- **等上游作者开一个组织仓，默认指向它**：语义最正确，但不在我们手里，且需要作者维护一份额外数据。可以先按现在这个默认值上线，等确实有组织仓再改默认值（改一行配置，不需要迁移）。

## 已知约束

- 上游评审可能不接受「默认依赖个人仓库」。退路是：代码只认配置项，默认值写在一处，评审若要求改就改那一处；PR 描述里主动说明这一点，别等对方发现。
- 个人仓库若迁移或改名，需要发一版插件改默认值。已改过配置的用户不受影响。
- 地图仓不可用时**不阻塞对话**：同步失败只记日志与计数，查询工具与提示词按「没有地图」降级，绝不因为拉不到数据就让聊天报错。
- 默认值只能在**一处**定义，测试断言这个真实默认值而不是另写一份常量——否则「默认地址被改错」这类回归永远测不出来。（默认值随配置项一起落地，见票 06；本 ADR 只定口径。）
