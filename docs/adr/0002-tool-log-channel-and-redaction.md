# 工具调用日志：统一 logger 通道与中文标签；明文留在控制台、脱敏留在转发

状态：已采纳（2026-10-17）。

四个 provider 执行器（OpenAI Chat Completions、OpenAI Responses、Claude、Gemini）的「工具调用/工具返回」日志原先通道混用（宿主 `logger` 与 `console`）、格式各异、失败路径记录不齐；参数脱敏只覆盖部分分支，且横跨日志与转发两处。现统一为：四处都走宿主 `logger.*`（获得时间戳、等级与错误落盘），格式固定为 `[Chatgpt][<提供方>][工具调用|工具返回][<工具名>]: …`，且**控制台日志保持明文**（仅操作者可见，排障要原文）；**参数脱敏只保留在会发送到会话的合并转发**。

## 考虑过的替代方案

- 日志与转发都脱敏（c0abe0b 的原始方向）：否——控制台日志的可见面只有操作者本人，脱敏的收益抵不过排障成本。
- Gemini 保留 `console.info` 以不受 `bot.log_level` 过滤：否——丢失时间戳/等级/错误落盘，得不偿失。

## 已知约束

- 工具日志从此受 `bot.log_level` 过滤；调高等级会连带看不到（原先 console 不受过滤）。
- Memory_Tool 的正文会出现在控制台日志里，这是有意为之：审查或重构时不要重新给日志加参数脱敏，先读本 ADR。
