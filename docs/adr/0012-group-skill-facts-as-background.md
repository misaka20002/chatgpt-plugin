# 群友 Skill 把已存个人事实当背景，而不是引文

状态：已采纳（2026-10-30）。需求与实现范围见 `.scratch/group-member-nuwa-v2/spec.md`。

群友 Skill 现在优先使用本群记忆采集的样本。除了原文，记忆系统还存着这个成员的 `user_group` 作用域事实——姓名、职业、长期偏好这类高价值信息，往往在最近 30 天的原文里没再出现。问题是怎么把它并入提炼链路。

## 备选方案

1. **当成证据**：给事实分配 `M####` 一类证据 ID，让它和原文一样被引用、进入 `references/evidence.md`，并参与「每条结论必须有证据」的服务端校验。
2. **完全不读**：只用原文，事实不参与。
3. **只作背景**：事实进入合成提示词的背景段，可以影响属性、价值观与反模式的判断，但不分配证据 ID、不进证据文件、不参与证据校验。

## 决定

选 **3**。原因：

- `evidence.md` 的语义是「短引文」，正文写着"以下短引文仅来自该成员的群聊文本"。事实是第三人称转述（"他常喝美式"），一旦混进去，"引文"就变成了改写，读产物的人无法再分辨哪句是本人原话。
- 校验层用证据 ID 保证"结论有据"。事实若可当证据，模型可以用一条概括去支撑任意结论，等于给校验开了一个后门。
- 完全不读又太浪费：本地原文常常只有几十条，姓名、职业这类信息恰好是原文里最短缺、事实里最完整的。

## 后果

- **代价**：原文稀少时，属性与价值观的覆盖度会偏低——事实不能直接支撑一条属性，只能帮模型在已有证据上做更准的归纳。
- **边界**：只读本群 `user_group`。跨群 `user` 事实会与产物中「样本仅来自一个群聊」的声明冲突，群公共 `group` 事实说的是群而不是人，两者都不读。
- **可逆性**：如果将来要在产物里显式标注"这条来自已存事实"，需要新增一套 `F####` 编号与独立的渲染段，而不是把事实混进证据文件。那是一次显式的产物结构变更，不是打开一个开关。
